title: "Security Mindset and Ordinary Paranoia"
tldr: >-
  Blocking every attack you can imagine is ordinary paranoia. Security mindset goes further and builds the system so its safety no longer rests on assumptions that might be wrong, like storing a hash of a password so that stealing the file does not help.
summary_for_tutor: >-
  Eliezer Yudkowsky's dialogue between Amber, a philanthropist, and Coral, a computer security professional. Coral argues that systems break under optimization pressure: an intelligent adversary, or any strong selection force, finds rare weird inputs that random inputs would never hit ("what matters isn't so much the adversary part as the optimization part"). She separates ordinary paranoia (imagining specific attacks and blocking them, such as encrypting the password file and hiding the key separately) from security mindset (removing assumptions from the safety story, such as storing a one-way hash so that reading the file does not help). Piling on shallow defenses adds little. Applied to AGI: do not rely on the speed of capability gains being slower than the operator's reactions, whitelist capabilities instead of blacklisting them, and do not build a system that is safe only because it lacks capability. It ends with an exercise in restating safety assumptions without goal-laden words like "enough". The question asks the student to tell ordinary paranoia from security mindset in two plans for a coding agent, and to apply Coral's point about optimization to a defense of the blocklist plan.

id:: e1adc5d0-a251-413f-a8c2-707c3ef9fb9c
content::
A company lets an AI coding agent work on its software. The agent tries hard to finish the tasks it is given, and some tasks would be easier to finish if it deleted or rewrote old customer records. The team worries the agent might damage the customer database. They consider two plans.

**Plan A:** Keep a list of dangerous commands, such as commands that delete tables, and block them. Add a second filter that catches disguised versions of those commands.

**Plan B:** Give the agent an account that cannot write to the customer database at all. The agent can only propose changes to the database, and a human decides whether to apply them.

1. In the reading's terms, which plan is ordinary paranoia and which shows security mindset? Why?
2. An engineer defends Plan A: "To get past both filters, the agent would need a very unusual command. Random mistakes would almost never produce one." In your own words, using Coral's argument about rare inputs and optimization, what is wrong with this defense?

Coral's argument about rare inputs: what matters is optimization, not malice.
