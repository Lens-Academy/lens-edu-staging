#### Question: Open
id:: c046f23c-700b-4d89-80a2-cbbbe45a77d0
content::
An AI company runs an internal research agent built on its newest model, which it cannot rule out is scheming. The agent runs machine-learning experiments for the company's researchers. To do that it:

- reads the researchers' experiment configurations and writes its results to a shared experiment tracker;
- submits training and evaluation jobs to the company's compute cluster through the cluster's job scheduler, using credentials issued to the agent;
- can point jobs at any dataset stored on the cluster, including a restricted dataset of a few gigabytes that holds hazardous biology protocols used in the company's dangerous-capability evaluations;
- its jobs can download software packages from the internet through the company's proxy.

The company worries about one specific harm: the agent launching a job that sends the restricted dataset, or part of it, to a server outside the company.

Propose a layered set of control measures against this harm that includes at least one measure that prevents it, one that detects it and one that responds to it. For each measure:

1. say whether it prevents the harm, detects it, or responds to it;
2. for each response, say whether it has to act before the relevant action takes effect or can act afterwards, and why;
3. name its main cost to the company, and one way a model that knows about the measure could get around it.
placeholder:: Aim for three to six measures. About 250 to 450 words.
assessment-instructions:: Score out of 100. 20: prevention, at least one measure that removes or narrows the agent's ability to carry out this exfiltration, labelled as prevention and tied to this attack path (for example permissions so the agent's jobs cannot read the restricted dataset or can only use it through an interface that returns evaluation scores and never the raw data, network isolation so jobs that can read restricted data have no route to the internet, limits on outbound bandwidth, an approval step before the agent gets new permissions, audited and locked-down scheduler and job code the agent cannot modify). 15: detection, at least one measure that notices an attempt, labelled as detection (for example a monitor that reviews each job specification before it runs, monitoring of outbound traffic volume and destinations, alerts when a job reads restricted data it has no evident need for, comparing the agent's behaviour with its normal baseline). 30: response timing, 15: the response for the sending step acts before the transfer takes effect (blocking, pausing for human review, or replacing the action before it runs), and 15: the reason, either that the harm cannot be undone (data that has left stays out, and splitting it into pieces only spreads the same permanent harm over more steps) or that a single job can do it, too fast to be reverted. Any further response the answer proposes is judged on its timing too: deduct 5 for each one placed wrongly, for example an after-the-fact review presented as able to recover data that has left. Judge timing by what the answer says the response does, not by its label: a response described as stopping the action before it runs counts as acting before, even if called "blocking" or "asynchronous". 35: costs and ways around. 15: a concrete, plausible main cost for most measures (for example slower experiments from review before execution, engineering effort to build isolation or a scores-only interface, blocked legitimate package downloads, reviewer time for false alarms, researchers losing flexibility). 20: a concrete way around for most measures, specific to that measure (for example hiding the data inside traffic that looks legitimate such as a package request, encoding it in results written to the experiment tracker if that is reachable from outside, writing a job specification that looks routine to a weaker monitor, requesting extra permissions with a plausible justification, having a job that can read the data hand it to a job that has network access, sending it in small pieces below volume alarms, modifying the scheduler or job code); a generic evasion ("the model could be sneaky") earns nothing. Give credit for each point whenever the answer shows the idea, in any wording. Cap at 55 if the answer: has no prevention, no detection or no response measure; does not place a response for the sending step before the transfer takes effect (omits the timing or puts it afterwards), unless it argues soundly that its prevention measures leave the agent no route for the transfer and says what would happen if they failed; places that response before the transfer but gives no reason tied to the harm being impossible to undo or done in a single action; names a concrete cost for fewer than half of its measures; or names a specific way around for fewer than half of its measures. Grade reasoning, not agreement: a learner who argues that one measure makes another unnecessary can score well if the argument holds for this deployment. A pass is roughly 60. Model answer, for the feedback, not a grading checklist: "Prevention: give the agent's jobs no direct read access to the restricted dataset; they can use it only through an evaluation interface that returns scores, never raw data, and any job that can touch restricted data runs with no network route out. Cost: engineering effort to build the interface and isolation, and less flexibility for researchers. Way around: request broader permissions with a plausible research justification, or get a job that can read the data to pass it to a job that has network access. Detection: a monitor reviews every job specification before it runs, and outbound traffic is watched for unusual volume and destinations. Cost: monitor compute, slower job starts and reviewer time for false alarms. Way around: write a job that looks routine to a weaker monitor, or hide the data in small pieces inside traffic that looks legitimate, such as package requests, below the volume alarms. Response: a job the monitor flags is blocked and held for human review before it runs, and the proxy blocks transfers to unapproved destinations as they happen. This has to act before the transfer, because a single job can send the data out and data that has left can never be recalled; splitting it into pieces only spreads the same permanent harm over more steps. Cost: delayed experiments and reviewer time. Way around: split the attack so that no single job looks suspicious enough to be held. After a flagged or blocked attempt, an incident investigation, revoking the agent's credentials and reviewing its past jobs can happen afterwards: they cannot undo a leak, but they inform what to tighten and whether to keep using the model. Unlike a harm that builds up slowly and can be reverted, such as gradually weakened evaluations, this one needs its response to act before the action takes effect."
feedback-instructions:: Name the strongest measure in the answer in one sentence, then the single change that would most improve the answer. If the learner let the sending step be handled only after the fact, point out that data cannot be recalled once it has left. If the learner asks about their score, explain plainly what earned and what lost points. At most five sentences. No generic praise.
