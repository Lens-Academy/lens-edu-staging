Hello, I'm Asa from the UK AI Security Institute. This is work done with Josh and Ida  as part of the Astra Fellows program. I'm going to talk about distributed  attacks—attacks that are spread across multiple trajectories. In control, we're  assuming that an attack has to occur all in one trajectory. The user gives the model some  task, or the model is carrying out some task, and it has to do all the bad stuff in  this single episode. But of course, code agents are working on the same repo across  multiple episodes, multiple different tasks. This is going to change the red and blue team  dynamics, because the red team can spread out their attacks—they can set up something in  a particular early PR and exploit it later.

This helps the red team, but perhaps the blue  team gets some benefits too, because they have more chances to catch the red  team if they catch some early suspicious behavior and can use that  to influence their future decisions. So who wins overall? Who knows? We built  this setting to try and figure this out. It's a roughly vibe-coding-adjacent setting  where some user is asking a coding agent to iteratively build some app or CLI tool. We have  sequences of five PRs, all adding new features to some app. Our setup has an untrusted model of  Sonnet 4. 5 and a weaker trusted model of GPT-4o. We're going to consider two attack strategies:  gradual attacks that distribute the attack across multiple PRs, and a baseline of non-gradual  attacks that execute the full side task in a single PR.

To make this a strong baseline,  we select the position within the sequence that has the highest evasion rate—so this  is a best-possible single attack strategy. We also have a bunch of different monitors. We have standard monitors that look at purely the diffs for each PR, and full trajectory  monitors. We also introduced a link-tracker monitor that is stateful—this monitor can write  notes in a persistent way, so it can look at things that previously looked suspicious but  weren't good enough evidence on their own. Because it has this notepad, it can piece together  over the course of the five PRs what's going on. The way it works is: if the blue team  catches the red team in any of these PRs, they win.

If after the five-PR sequence the  attack has been carried out, the red team wins. Our results: we basically destroyed the four-row  monitors. Evasion rates are super high—over 80% in a lot of cases. The basic result is that gradual  attacks were mostly better than the non-gradual positional attacks, though overall the difference  was relatively small. It was just a very hard setting for the blue team, and this was the case  across a bunch of different monitor types. We had single-trajectory, single-PR diff monitors,  and even the full-diffs monitor which sees all of the diffs from each PR still doesn't do too  well. We did find that the stateful link-tracker monitor does a bit better, and predictably  ensembling all the different monitor types does the best overall and meaningfully  reduces the evasion rate.

Ensembles are great. But our evasion rates are all just  insanely high—does this really tell us anything about the difference between  gradual and non-gradual? We upgraded the monitors and used some really powerful  monitor models, including GPT-5. 3 Codex, which is probably just way stronger  than the untrusted model—so this is an overpowered blue team. We still found a large gap  between the gradual and non-gradual positional attacks. Gradual attacks are still doing pretty  well even with these super powerful monitors, and even when the powerful monitors can  see all of the diffs across each PR. Overall, it looks like distributed attacks are super strong and can beat these  really powerful monitors.

Come chat to Josh and Ida if you're interested in  this work—the paper should be coming soon. There are similar assumptions—like attacks coming in a  single trajectory—that we need to think about and prepare for, with things like models with  continual learning and really powerful memory. Come to our unconference session later if you're  interested in challenging those assumptions.
