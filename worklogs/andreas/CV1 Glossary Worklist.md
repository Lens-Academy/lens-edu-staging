## How the check was done

- Every acronym on every page, with the first required page where a learner meets it and whether it is spelled out there.
- Each judged by the five rules in [[../../AI Guide/Writing Glossary Entries]]: a learner may not know it, the course has not explained it, the page does not explain it, the first use has that meaning, and understanding it matters.
- Not covered: widgets, which the glossary does not reach, and the meeting docs.

## Open points

1. **Pages written inside module files.** The course overview, the unit welcomes and the feedback pages live inside module files. The guide documents `glossary_terms` for lens files only, so it is not clear that these pages can list words. ASI, IAEA and MIRI first appear on the overview; their lines go on the first lens file that uses them.
2. **Collapsed boxes.** All six acronyms on "Policies Must Be Effective and Feasible" first appear inside collapsed boxes. The guide says words in `:::hide` boxes never get a line and says nothing about collapsed callouts. Check one, RSPs, on staging once built.
3. **"M&V" contains an ampersand.** Whether the matcher treats it as one word is untested; check it on staging too.
4. **How the lists go in.** The guide asks an AI to add the lists as suggestions, but a suggestion in a page header breaks the header (the log's section 9). As on "Game Theory", direct edits, logged.
5. **Widgets.** Unit 1's introduction widgets carry acronyms the glossary cannot reach (RAND, CNAS, CSET, NIST, CAISI). Fixing those means changing the widget's own text.
6. **Optional pages.** The guide counts a word first explained on an optional page as still new on required pages, so the plan lists words on required pages. Optional pages that use them earlier, such as AI 2027 with FLOP, could get their own lists later.
